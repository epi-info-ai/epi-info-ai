# Environmental Epidemiology coalition demo

Status: afternoon demonstration runbook for the bounded v0.2.0 candidate

Audience: National Center for Environmental Health collaborators, environmental
epidemiologists, GIS/data stewards, trainers, and Epi Info practitioners.

## Demonstration claim

Epi Info AI can distribute a governed environmental capability separately from
the projects that teach and exercise it. The current candidate already combines
portable browser projects, familiar analysis, an emerging typed GIS kernel,
mapping, runbooks, provenance, and offline operation. It does **not** yet claim
live provider integration, an approved exposure model, causal inference, or K09
advanced spatial-statistical validation.

## Twelve-minute run of show

### 0:00–2:00 — Epi Info AI in general

1. Open the published application and point out the visible version.
2. Explain browser-first/offline-first project storage and the familiar Forms,
   Enter Data, Visual Dashboard, Classic Analysis, Maps, and StatCalc modules.
3. Open File > Import Example Project briefly to show the checksummed teaching
   catalog, then close it without importing.

Message: the familiar Epi Info workflow is being rebuilt behind typed,
testable, auditable browser boundaries rather than replaced by a black box.

### 2:00–4:00 — Import the capability package

1. Open Help > Capability Packages.
2. Select **Environmental Epidemiology** and choose **Preview package**.
3. Show publisher, exact revision, declared inert artifacts, installation
   approval, scientific-execution status, and requested authority.
4. Choose **Verify and install inert package**.

Message: package installation verifies declarative assets only. It installs no
JavaScript/WASM/model, contacts no provider, runs no program, and grants no
network or GIS authority.

### 4:00–8:00 — Import and use the teaching project

1. Open File > Import Example Project.
2. Import **Environmental Heat and Health Candidate**.
3. Show its 12 clearly labeled synthetic records in Enter Data.
4. Open Classic Analysis, load `environmental-heat-health-tour`, and run it.
5. Move quickly through QUALITY, LIST, heat-category FREQ, mean heat index,
   the binary TABLES result, and the bar chart.

Message: data, program, runbook, and map travel together and remain inspectable.
The output is descriptive teaching evidence, not a causal conclusion.

### 8:00–10:00 — Reveal the emergent GIS kernel

1. Open Help > GIS Kernel Lab.
2. Keep **Environmental heat-health observations (synthetic)** selected.
3. Review the operation, exact input, CRS, limits, output disclosure, and the
   absence of network/project-mutation authority.
4. Run the bounded inspection and show the human-readable result plus the full
   machine-readable receipt.

Message: the environmental package harnesses an application-shipped kernel. It
does not bring arbitrary GIS code or bypass review.

### 10:00–11:00 — Show the map

Return to the application and open Maps. Show the restored point layer and its
signed, five-decimal coordinates. Explain that map rendering is presentation;
the typed plan and receipt are the processing evidence.

### 11:00–12:00 — Make the coalition ask

Ask NCEH partners to co-own four concrete artifacts:

1. the first scientifically meaningful heat/health question and synthetic or
   disclosure-cleared validation fixture;
2. provider metadata, units, terms, temporal/spatial linkage, missingness, and
   provenance contracts for CDC, NOAA, and Copernicus sources;
3. expected results and independent validation for exposure windows and later
   health-effect methods; and
4. privacy, field usability, accessibility, training, and scientific sign-off.

## Consequential package contributions

- reproducible environmental asset discovery and reviewed retrieval plans;
- provenance-preserving offline snapshots rather than irreproducible live-only
  queries;
- explicit spatial and temporal exposure linkage with units and quality flags;
- privacy-preserving geography and governed `epi-gis` operations;
- heat, air quality, water, climate, built-environment, and disaster-response
  teaching modules sharing one platform contract;
- transparent lag/window construction and later case-crossover/time-series
  methods after independent validation; and
- NCEH-curated project/package distribution with CI evidence and runbooks for
  field epidemiology training.

## Demo safety and fallback

- Use the published GitHub Pages mirror in a fresh browser profile.
- Keep the GitLab Pages link and a local `pnpm run preview` tab available.
- Do not depend on a live foundation model or environmental provider.
- Do not demo K09 advanced spatial statistics.
- If WebGL/basemap access is unavailable, show the packaged layer inventory and
  GIS Kernel Lab receipt; the scientific workflow remains demonstrable offline.
